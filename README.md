# 연극공연지원사업 정보

연극 공연·단체를 위한 지원사업(중앙정부/공공기관, 지역문화재단, 민간/기업)뿐 아니라 오디션/캐스팅, 공모전, 워크숍 등 개별 공고까지 모아 보여주는 정적 사이트입니다. 빌드 도구 없이 순수 HTML/CSS/JS로 동작하며 GitHub Pages로 배포됩니다.

## 로컬 실행

```bash
python -m http.server 8000
```

`http://localhost:8000` 접속. (`index.html`을 `file://`로 직접 열면 `fetch`가 실패합니다.)

## 파일 구조

- `index.html`, `styles.css`, `app.js` — 정적 프론트엔드
- `data/programs.json` — 지원사업 데이터 (이 파일이 매일 자동 갱신됨)
- `data/sources.json` — 개괄 검색 대상 기관 마스터리스트(중앙정부/공공기관, 광역·기초 문화재단, 민간·기업재단, 총 51곳). "지원사업 데이터 갱신" 루틴이 이 목록을 순회하며 WebSearch를 수행함
- `data/board_sources.json` — 게시판 단위 상세 수집 대상 핵심 기관 14곳. "게시판 공고 갱신" 루틴이 이 목록의 각 기관 게시판을 WebFetch로 직접 열어 개별 공고(지원사업/오디션·캐스팅/공모전/워크숍)를 뽑아낸다. wearts.co.kr 같은 로그인 필요 사이트는 자동화할 수 없어서, 로그인 없이 공개된 각 기관 공식 게시판을 직접 보는 방식으로 비슷한 디테일을 확보함

## `data/programs.json` 스키마

```json
{
  "last_updated": "ISO 8601 timestamp",
  "programs": [
    {
      "id": "사업명+주관기관 기반 고유 슬러그",
      "사업명": "string",
      "주관기관": "string",
      "카테고리": "중앙정부/공공기관 | 지역문화재단 | 민간/기업",
      "지역": "string | null (전국 단위면 null)",
      "지원대상": "string",
      "지원내용": "string (자유 텍스트, 금액/규모)",
      "신청기간_시작": "YYYY-MM-DD | null",
      "신청기간_마감": "YYYY-MM-DD | null",
      "원문상태": "string | null (예: 상시모집, 예산 소진 시까지)",
      "신청방법": "string",
      "신청링크": "URL | null",
      "원본공고링크": "URL (필수)",
      "문의처": "string | null",
      "최종확인일": "YYYY-MM-DD",
      "비고": "string | null",
      "유형": "지원사업 | 오디션/캐스팅 | 공모전 | 워크숍/교육"
    }
  ]
}
```

모집중/예정/마감/상시 상태는 저장하지 않고 `app.js`가 오늘 날짜 기준으로 계산합니다. `카테고리`는 "누가 올렸나"(중앙정부/지역재단/민간), `유형`은 "무슨 공고인가"(지원사업/오디션/공모전/워크숍)를 나타내는 별도 축입니다. `최종확인일`이 오늘 기준 3일 이내면 화면에 NEW 뱃지가 붙습니다.

## 자동 갱신 작업 (예약 루틴 2개)

**1. 지원사업 데이터 갱신** (`trig_01Ex2sQaBobM9Xmhy42LC2z4`, 매일 08:00 KST) — 기관 단위 개괄 검색:

1. 기존 `data/programs.json` 읽기
2. `data/sources.json`을 읽고 그 안의 tier1~tier4 전체 기관(51곳)을 순회하며 각 기관명 기준으로 WebSearch 수행 + "연극 지원사업 공모 [연도]" 등 일반 검색 병행
3. **이번 검색에서 실제로 확인된 내용만 반영** — 모델의 사전 지식으로 필드를 채우지 않음. 불확실한 값은 `null` + `비고`에 "확인필요"
4. `사업명`+`주관기관` 기준으로 dedupe 병합 (기존 갱신 또는 신규 추가, `최종확인일` 갱신)
5. 보존 규칙: 마감일이 지난 지 14일 넘은 항목만 제거. 검색에 단순히 안 나왔다는 이유로는 삭제하지 않음
6. 쓰기 전 검증: JSON 유효성, `id` 중복 없음, 날짜 형식, 필수 필드(사업명/주관기관/카테고리/원본공고링크) 비어있지 않음
7. `last_updated` 갱신. 변경 없으면 커밋 스킵, 있으면 커밋(`chore: 지원사업 데이터 갱신 (YYYY-MM-DD)`) 후 push

**2. 게시판 공고 갱신** (별도 루틴, 매일 08:00 KST) — 핵심 기관 게시판 단위 상세 수집:

1. `data/board_sources.json`의 14개 기관을 순회. 게시판URL이 있으면 그걸, 없으면 홈페이지에서 공모/공지/모집 게시판을 찾아 `WebFetch`로 최근 게시글 목록을 가져옴
2. 연극·공연 관련 게시글(지원사업, 오디션/캐스팅, 공모전, 워크숍 등)만 골라 제목·마감일·한 줄 요약·원문링크를 추출 (실제 확인된 내용만)
3. `data/programs.json`과 제목+기관명 기준 병합 (1번 루틴과 동일한 병합/보존/검증 규칙 재사용)
4. 변경 있으면 커밋(`chore: 게시판 공고 갱신 (YYYY-MM-DD)`)/push, 없으면 스킵

두 루틴을 분리한 이유: 51개 기관 전체를 매일 WebSearch하는 작업과 14개 기관 게시판을 WebFetch로 훑는 작업을 하나로 합치면 실패/시간초과 위험이 커진다. 분리하면 한쪽이 실패해도 다른 쪽엔 영향이 없다.
